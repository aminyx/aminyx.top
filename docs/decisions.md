# Архитектурные решения (ADR) — aminyx.top

Что решено не делать и почему.

## Service Worker — НЕ внедрять (2026-08-10)

KPI сайта — клик в Telegram, который оффлайн не работает; оффлайн-копия визитки ценности не создаёт. Главный риск — GitHub Pages не даёт HTTP-заголовков: протухший/забагованный SW нечем убить (нет Clear-Site-Data), лечение — деплой no-op SW и ожидание до 24 ч, пока браузеры его подхватят. Vite и так отдаёт хешированные ассеты с долгим кешем. Если когда-нибудь понадобится: network-first для навигаций + версионированный кеш + заранее закоммиченный килсвитч.

## Скролл-прогресс-бар — НЕ делать

Страница короткая, прогресс-бар ей не нужен.

## Бургер-меню на Popover API — отложено

Текущее меню уже даёт Esc, scroll-lock, inert, возврат фокуса и закрытие по брейкпоинту. Перевод на popover потребовал бы двойного пути (фолбэк для старых браузеров) — две реализации одного меню хуже одной проверенной. Пересмотреть, когда можно будет бросить фолбэк.

## light-dark() рефакторинг темизации — отложено

Инженерная выгода (меньше дублирования токенов) не окупает риск регрессии двух отлаженных тем; браузеры без поддержки потребовали бы третьей копии токенов через @supports. Пересмотреть при следующем большом редизайне.

## .well-known/traffic-advice — невозможно и не нужно

Chrome требует Content-Type application/trafficadvice+json; GitHub Pages отдаёт файлы без расширения как application/octet-stream и заголовки не переопределить. К тому же файл умеет только ОГРАНИЧИВАТЬ префетч-прокси, который и так работает.

## share_target / Badging / registerProtocolHandler — не применимы

Все требуют установленной PWA-аудитории или собственной URL-схемы; у визитки их нет.

## Rapier-физика для осколков узлов — НЕ подключать

Осколки ни с чем не сталкиваются — вся «физика» это баллистика с гравитацией
и затуханием: 40 строк в sim.js, рендер в существующем пайплайне точек.
@react-three/rapier добавил бы ~1 МБ WASM ради визуально идентичного эффекта —
против бренда скорости (Lighthouse 100). Пересмотреть, только если появится
настоящая механика столкновений.

## Кинетическая типографика hero (вариативный вес от курсора) — НЕ делать

Прыгающие веса меняют ширину глифов → строки дышат и дёргаются. Прямое
противоречие принципу: «типографика швейцарской строгости, чтобы
кинематика не съела читаемость». Кинематику несёт сцена, типографика — якорь.
По той же причине не делаем «магнитные» кнопки.

## Тёмная динамическая фавиконка (media в SVG) — не нужна

Знак несёт собственную тёмную плашку #0b0c0f и читается на вкладках обеих тем; media-запросы внутри favicon-SVG Safari всё равно не применяет.
