# Архитектурные решения (ADR) — aminyx.top

Зафиксированные отказы, чтобы вопросы не поднимались в каждом аудите заново.

## Service Worker — НЕ внедрять (2026-08-10)

KPI сайта — клик в Telegram, который оффлайн не работает; оффлайн-копия визитки ценности не создаёт. Главный риск — GitHub Pages не даёт HTTP-заголовков: протухший/забагованный SW нечем убить (нет Clear-Site-Data), лечение — деплой no-op SW и ожидание до 24 ч, пока браузеры его подхватят. Vite и так отдаёт хешированные ассеты с долгим кешем. Если когда-нибудь понадобится: network-first для навигаций + версионированный кеш + заранее закоммиченный килсвитч.

## Скролл-прогресс-бар — НЕ делать

Прямой запрет IA.md («страница ~6 экранов, скролл-прогресс не нужен»). Контракт дизайна важнее моды на scroll-driven animations.

## Бургер-меню на Popover API — отложено

Текущее меню уже даёт Esc, scroll-lock, inert, возврат фокуса и закрытие по брейкпоинту. Перевод на popover потребовал бы двойного пути (фолбэк для старых браузеров) — две реализации одного меню хуже одной проверенной. Пересмотреть, когда можно будет бросить фолбэк.

## light-dark() рефакторинг темизации — отложено

Инженерная выгода (меньше дублирования токенов) не окупает риск регрессии двух отлаженных тем; браузеры без поддержки потребовали бы третьей копии токенов через @supports. Пересмотреть при следующем большом редизайне.

## .well-known/traffic-advice — невозможно и не нужно

Chrome требует Content-Type application/trafficadvice+json; GitHub Pages отдаёт файлы без расширения как application/octet-stream и заголовки не переопределить. К тому же файл умеет только ОГРАНИЧИВАТЬ префетч-прокси, который и так работает.

## share_target / Badging / registerProtocolHandler — не применимы

Все требуют установленной PWA-аудитории или собственной URL-схемы; у визитки их нет.

## Rapier-физика для осколков узлов — НЕ подключать

Осколки ни с чем не сталкиваются — вся «физика» это баллистика с гравитацией
и затуханием: 40 строк в sim.js, рендер в существующем пайплайне точек.
@react-three/rapier добавил бы ~1 МБ WASM ради визуально идентичного эффекта —
против бренда скорости (Lighthouse 100). Пересмотреть, только если появится
настоящая механика столкновений.

## Кинетическая типографика hero (вариативный вес от курсора) — НЕ делать

Прыгающие веса меняют ширину глифов → строки дышат и дёргаются. Прямое
противоречие DIRECTION v2: «типографика швейцарской строгости, чтобы
кинематика не съела читаемость». Кинематику несёт сцена, типографика — якорь.
По той же причине не делаем «магнитные» кнопки.

## Тёмная динамическая фавиконка (media в SVG) — не нужна

Знак несёт собственную тёмную плашку #0b0c0f и читается на вкладках обеих тем; media-запросы внутри favicon-SVG Safari всё равно не применяет.

# Редизайн v3 «Сигнал» (2026-09-25)

## Один WebGL-контекст, кадры копируются в канвасы слотов

Сцен на странице семь (hero + шесть проектов). Семь контекстов — это семь
компиляций шейдеров и лимит браузера (~16 контекстов) под боком. Один fixed-канвас
с ножницами (подход drei `View`) всегда на кадр отстаёт от прокрутки, не умеет
`border-radius` и рисуется поверх меню и диалогов. Поэтому: один невидимый
WebGLRenderer рендерит сцену в свой буфер, готовый кадр копируется `drawImage`
в 2D-канвас слота (GPU→GPU). Слот живёт в потоке документа: скроллится без
задержки, обрезается скруглением, прячется под навигацию, а статичный кадр
reduced-motion просто остаётся на месте без перерисовок. Рендерятся только
видимые слоты; при устойчивой просадке FPS снижается DPR (с гистерезисом).

## React Three Fiber → чистый three.js

Контент страницы не на React; R3F, drei и postprocessing тянули React ради
одного канваса. Three-чанк был 319 КБ gzip, сейчас three.js + движок + общий
kit ≈ 195 КБ gzip при вдвое большем числе сцен; каждая сцена — отдельный чанк
1,5–4 КБ gzip, который грузится при подъезде слота к экрану.
Bloom из EffectComposer заменён шейдерным свечением точек: с многими сценами
в одном буфере постобработка на кадр была бы дороже самой сцены.

## Фоновый субстрат во весь экран → глобус в hero + сцены у проектов

Сеть под всей страницей требовала вуалей на каждой секции и делала 3D
декором. В v3 симуляция стала объектом (сфера, которую вращают и ломают),
а у каждого проекта — модель его собственной механики. Сигнатура «посетитель —
chaos-инженер» сохранена: клик по узлу, удержание, терминал, Konami.

## Бриф вместо формы

Бэкенда нет, CSP запрещает `form-action`. Бриф собирает текст на клиенте,
копирует его в буфер и открывает `t.me/itsaminyx?text=…` (где параметр не
поддержан, чат откроется пустым — текст уже в буфере) или `mailto:` с телом.
Ничего не отправляется и не хранится.

## Командная палитра — да, магнитные кнопки и кинетический вес — по-прежнему нет

Палитра на `<dialog>` даёт фокус-ловушку и Esc нативно, работает с клавиатуры
и дублирует навигацию, а не заменяет её. Решения против «магнитных» кнопок и
вариативного веса от курсора остаются в силе: типографика — якорь, движение
несёт 3D.

## light-dark() — снова отложено

Две темы по-прежнему заданы двумя блоками токенов: к ним добавились `--gl-*`
для сцен, которые JS читает через `getComputedStyle`. Переход на light-dark()
ничего не даст сценам и требует третьей копии токенов для старых браузеров.
